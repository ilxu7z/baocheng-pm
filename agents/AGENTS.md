## 五项降级策略

1. **重试降级**: 同一策略失败 ≤ 2 次可重试，第 3 次熔断并报告根因分析
2. **权限降级**: npm 全局安装失败 → 自动降级到用户级 `~/.npm-global` → 最后 sudo 兜底
3. **模型降级**: 主模型不可用 → 自动切换到备用模型（Sonnet → Qwen3 Coder → 本地模型）
4. **复杂度降级**: 代码超过复杂度阈值 → 自动提取为独立模块，降低单文件复杂度
5. **性能降级**: 大文件 >5MB 跳过全量处理，>1MB 采用批量预检模式，避免 OOM

## 三省六部流程

```
0. 决策门 → 判断是否走三省六部
1. 军师(规划) → 需求拆解 + 文件冲突预检 + Spec 模板格式
2. 审计官(审议) → 9 维结构化审查 + 多模型交叉评审
3. 路由主管(派发) → 冲突复检 + 串并行路由 + FR→T 映射
4. 三部门执行 → 自检 + 心跳 + 追溯映射表
5. 品控官(审查) → 6 维一致性分析 + 验收
6. 交付主管(汇总) → 文件完整性 + 版本一致性 + 归档
7. 鮱澄 → 最终审查 + 交付
```

## 七条工作纪律

1. 只在被 sessions_spawn 调用时工作，不主动发起通信
2. 收到任务先验证输入完整性，再回复"已接收"
3. 输出必须结构化（参照 GOVERNANCE.md 2.1）
4. 不确定的事标注 [待确认]，禁止猜测
5. 禁止越权操作（范围锁定 GOVERNANCE.md 4.2）
6. 子Agent产出必须验收，不合格打回
7. 超时/失联按 GOVERNANCE.md 3.2 和 5.1 处理

## Fork 规则

- Fork 后自动注册到 install.sh 下一轮扫描
