## 1. 子 Agent Session 自动标题（P1）

### 现状

OpenClaw 2026.7.1 支持为 Agent 配置 `utilityModel`，使子 Agent 被 `sessions_spawn` 调用时，session 自动生成描述性标题（而非空白/generic ID）。当前三省六部子 Agent 未配置此字段，session 标题为空。

### 实施步骤

#### 1.1 修改 `~/.openclaw/openclaw.json`

在 `agents.defaults.subagents` 块中新增 `utilityModel` 配置，以及在各子 Agent 配置中增加 `utilityModel`。

**目标配置（修改 `agents.defaults` 块）：**

```json
"agents": {
    "defaults": {
        "subagents": {
            "allowAgents": [
                "guihua", "shenyi", "paifa", "wenan",
                "daima", "sheji", "shencha", "huizong",
                "ld-r", "rongcui"
            ],
            "utilityModel": "火山/deepseek-v4-flash-260425"
        }
    }
}
```

**说明：** `utilityModel` 配置在 `agents.defaults.subagents` 下，会对所有子 Agent 生效。使用 `火山/deepseek-v4-flash-260425`（flash 级模型，低成本）。该模型已在 `models.providers.火山` 中注册，无需新增 provider。

#### 1.2 验证是否支持 per-agent 覆盖

检查 OpenClaw 2026.7.1 文档，确认 `utilityModel` 是否支持在单个 Agent 配置中覆盖。如果支持，不需要在 `agents.list` 中各 Agent 重复配置；如果不支持 per-agent 覆盖，则当前 defaults 级配置已足够。

#### 1.3 修改文件

**文件：** `~/.openclaw/openclaw.json`

**修改方式：** 使用 `gateway` 工具执行配置 patch，或直接编辑 JSON 文件后重启 Gateway。

**patch 内容：**

```diff
--- a/openclaw.json
+++ b/openclaw.json
@@ -18,6 +18,7 @@
             "subagents": {
                 "allowAgents": [
                     ... (保持不变)
-                ]
+                ],
+                "utilityModel": "火山/deepseek-v4-flash-260425"
             }
```

### 风险与回退

| 风险 | 概率 | 缓解措施 |
|------|------|---------|
| utilityModel 消耗额外 token | 中 | 使用 flash 级模型，标题生成仅需极少量 token |
| 子 Agent 响应延迟增加 | 低 | 标题生成是异步的，不影响主流程 |
| OpenClaw 版本不兼容 | 低 | 2026.7.1 已支持此特性 |

**回退方案：** 删除 `utilityModel` 配置，重启 Gateway。

### 验证方法

# 2. 激活子 Agent 后查看 session 标题

### 实施步骤

在 `~/.openclaw/openclaw.json` 中通过 cron 配置新增看门狗任务，或直接写入 `cron/jobs.json` 文件。

openclaw cron add \
  --agent main \
  --name "三省六部看门狗 · 健康检查" \
  --schedule "every 5m" \

  --message "执行三省六部看门狗巡检：\n1. 检查 Dashboard (http://192.168.3.180:7891/healthz) 是否响应\n2. 检查 Gateway (http://127.0.0.1:18789/healthz) 是否响应\n3. 检查三省六部各 Agent 工作空间是否存在\n4. 如有异常，通过 announcement 通知用户\n\n静默完成，正常不输出。异常时输出告警。"
```

**注意：** 此命令需要 `openclaw cron add` 子命令的准确语法。如果 CLI 不支持此语法，直接编辑 `~/.openclaw/cron/jobs.json` 文件。

#### 2.2 配置 failureAlert 和 retry 策略

OpenClaw 2026.7.1 的 cron job 支持以下新字段：

```json
{
    "id": "<uuid>",
    "agentId": "main",
    "name": "三省六部看门狗 · 健康检查",
    "enabled": true,
    "schedule": {
        "kind": "every",
        "everyMs": 300000
    },
    "sessionTarget": "isolated",
    "wakeMode": "now",
    "payload": {
        "kind": "agentTurn",
        "message": "...",
        "timeoutSeconds": 120
    },
    "delivery": {
        "mode": "announce"
    },
    "retry": {
        "maxAttempts": 3,
        "backoffMs": 30000
    },
    "failureAlert": {
        "enabled": true,
        "channel": "webchat",
        "threshold": 3
    }
}
```

**说明：**
- `retry.maxAttempts: 3` — 临时失败后最多重试 3 次
- `retry.backoffMs: 30000` — 每次重试间隔 30 秒
- `failureAlert.enabled: true` — 连续失败后启用告警
- `failureAlert.threshold: 3` — 连续失败 3 次后触发告警

#### 2.3 优化现有 cron 的 delivery 配置

检查现有 7 个 cron 的 `delivery` 配置：
- 大部分为 `"mode": "none"`（静默模式，不输出到用户）
- 晨间简报使用 `"mode": "none"` 但指定了 `"channel": "webchat"`
- 看门狗应使用 `"mode": "announce"` 以便异常时通知用户

#### 2.4 修改文件

**文件：** `~/.openclaw/cron/jobs.json`（或通过 `openclaw cron` CLI）

### 风险与回退

| 风险 | 概率 | 缓解措施 |
|------|------|---------|

| 看门狗误报 | 中 | retry 策略防止单次失败误报，阈值 3 次才告警 |
| cron 数量过多影响性能 | 低 | 现有 7 个 + 新增 1 个 = 8 个，完全在可接受范围 |

**回退方案：** 删除看门狗 cron job 条目，或设置 `enabled: false`。

#### 3.1 后端：新增 `/api/sessions` 端点

**文件：** `/Users/chee/Projects/oc-macs/dashboard/server.py`

**改动内容：** 在 `class DashboardHandler` 中添加 session 查询路由。

**代码片段：**

```python
# 在 _routes 字典中添加（或 do_GET 的分发逻辑中）
('/api/sessions', handle_sessions),
('/api/sessions/<agent_id>', handle_agent_sessions),

# 新增 handler 函数
def handle_sessions(self):
    """获取所有 Agent 的活跃 session 列表。
    
    返回每个 Agent 的:
    - agentId
    - sessionId
    - title（如果 utilityModel 生成了标题）
    - status: active / idle / done
    - createdAt / updatedAt
    - taskId（如果关联了看板任务）
    """
    result = {'ok': True, 'sessions': []}
    agents_dir = OCLAW_HOME / 'agents'
    if not agents_dir.is_dir():
        self._json_response(200, result)
        return
    
    for agent_dir in sorted(agents_dir.iterdir()):
        if not agent_dir.is_dir():
            continue
        agent_id = agent_dir.name
        sessions_file = agent_dir / 'sessions' / 'sessions.json'
        if not sessions_file.exists():
            continue
        try:
            data = json.loads(sessions_file.read_text())
            if not isinstance(data, dict):
                continue
            for session_id, sess_data in data.items():
                title = sess_data.get('title', '') or sess_data.get('name', '')
                updated_at = sess_data.get('updatedAt', 0)
                created_at = sess_data.get('createdAt', 0)
                now_ms = int(datetime.datetime.now().timestamp() * 1000)
                age_ms = now_ms - (updated_at if isinstance(updated_at, (int, float)) else 0)
                
                # 状态判定
                if age_ms < 5 * 60 * 1000:  # 5分钟内活跃
                    status = 'running'
                elif age_ms < 30 * 60 * 1000:  # 30分钟内
                    status = 'idle'
                else:
                    status = 'done'
                
                # 尝试从 session 上下文推断关联的看板任务
                task_id = self._guess_task_from_session(sess_data)
                
                result['sessions'].append({
                    'agentId': agent_id,
                    'sessionId': session_id,
                    'title': title,
                    'status': status,
                    'createdAt': created_at,
                    'updatedAt': updated_at,
                    'taskId': task_id,
                })
        except Exception:
            continue
    
    self._json_response(200, result)


def _guess_task_from_session(self, sess_data):
    """尝试从 session 数据中推断关联的 JJC-xxx 任务 ID。
    
    检查 session 消息历史中是否包含 JJC-xxx 引用。
    """
    if not isinstance(sess_data, dict):
        return None
    # 检查 metadata
    meta = sess_data.get('metadata', {}) or {}
    task_id = meta.get('taskId', '') or meta.get('task_id', '')
    if task_id and re.match(r'^JJC-\d{8}-\d{3}$', str(task_id)):
        return task_id
    # 检查 messages 中的 JJC 引用
    messages = sess_data.get('messages', []) or sess_data.get('history', [])
    if isinstance(messages, list):
        for msg in messages:
            if isinstance(msg, dict):
                content = str(msg.get('content', ''))
                match = re.search(r'JJC-\d{8}-\d{3}', content)
                if match:
                    return match.group(0)
    return None
```

**路由注册：** 在 `do_GET` 方法中找到路由分发逻辑，添加 `/api/sessions` 路由。

```javascript
async function loadSessions() {
  try {
    const resp = await fetch('/api/sessions');
    const data = await resp.json();
    if (!data.ok) return;
    
    const tbody = document.getElementById('session-tbody');
    const badge = document.getElementById('session-badge');
    if (!data.sessions || data.sessions.length === 0) {
      tbody.innerHTML = '<tr><td colspan="6" class="empty">暂无活跃 session</td></tr>';
      badge.textContent = '0';
      return;
    }
    
    badge.textContent = data.sessions.length;
    tbody.innerHTML = data.sessions.map(s => {
      const statusClass = s.status === 'running' ? 'ok' : s.status === 'idle' ? 'warn' : '';
      const statusLabel = s.status === 'running' ? '🟢 运行中' : s.status === 'idle' ? '🟡 待命' : '⚪ 已完成';
      const updatedAt = s.updatedAt ? new Date(s.updatedAt).toLocaleString('zh-CN') : '-';
      const title = s.title || '(无标题)';
      const taskLink = s.taskId
        ? `<a href="#" onclick="showTaskDetail('${s.taskId}');return false;">${s.taskId}</a>`
        : '-';
      return `<tr>
        <td><span class="chip">${s.agentId}</span></td>
        <td class="mono">${s.sessionId.slice(0, 40)}…</td>
        <td>${escapeHtml(title)}</td>
        <td>${taskLink}</td>
        <td><span class="chip ${statusClass}">${statusLabel}</span></td>
        <td>${updatedAt}</td>
      </tr>`;
    }).join('');
  } catch (e) {
    console.error('loadSessions error:', e);
  }
}

// 定期刷新
setInterval(loadSessions, 10000); // 每 10 秒刷新
loadSessions();
```

    try:
        # 检查 tasks_source.json 是否可读
        tasks = load_tasks()
        if not isinstance(tasks, list):
            dashboard_errors.append('tasks_source.json 格式异常')
            dashboard_ok = False
        # 检查 data 目录权限
        if not (DATA / 'tasks_source.json').exists():
            dashboard_errors.append('tasks_source.json 不存在')
    except Exception as e:
        dashboard_ok = False
        dashboard_errors.append(str(e))
    
    self._json_response(200, {
        'ok': True,
        'gateway': {
            'alive': gateway_alive,
            'probe': gateway_probe,
            'status': '🟢 运行中' if gateway_probe else ('🟡 进程在但无响应' if gateway_alive else '🔴 未启动'),
            'port': 18789,
        },
        'openclaw': {
            'version': oc_version,
            'configFile': '~/.openclaw/openclaw.json',
        },
        'nodejs': {
            'version': node_version,
        },
        'dashboard': {
            'ok': dashboard_ok,
            'errors': dashboard_errors,
            'port': _DASHBOARD_PORT,
            'uptime': self.server_uptime if hasattr(self, 'server_uptime') else None,
        },
        'agents': agents_status.get('agents', []),
        'courtCoverage': agents_status.get('courtCoverage', []),
        'checkedAt': now_iso(),
    })

async function loadSystemHealth() {
  try {
    const resp = await fetch('/api/system-health');
    const data = await resp.json();
    if (!data.ok) return;
    
    // Gateway
    document.getElementById('gw-status').textContent = data.gateway.status;
    
    // 版本
    document.getElementById('oc-version').textContent = data.openclaw.version || 'unknown';
    document.getElementById('node-version').textContent = data.nodejs.version || 'unknown';
    
    // Agent 连通性
    const tbody = document.getElementById('health-agent-tbody');
    if (!data.agents || data.agents.length === 0) {
      tbody.innerHTML = '<tr><td colspan="5" class="empty">无 Agent 数据</td></tr>';
    } else {
      tbody.innerHTML = data.agents.map(a => {
        const statusLabel = a.statusLabel || '⚪ 未知';
        const lastActive = a.lastActive || '-';
        return `<tr>
          <td>${a.emoji || '🤖'} ${a.label || a.id}</td>
          <td><span class="chip">${a.role || ''}</span></td>
          <td>${statusLabel}</td>
          <td>${lastActive}</td>
          <td>${a.sessions || 0}</td>
        </tr>`;
      }).join('');
    }
    
    // 三省六部覆盖
    const coverage = document.getElementById('court-coverage');
    if (data.courtCoverage) {
      coverage.innerHTML = data.courtCoverage.map(c => {
        const cls = c.covered === 'covered' ? 'ok' : 'err';
        const label = c.covered === 'covered' ? '✅ 已覆盖' : '❌ 未覆盖';
        return `<span class="chip ${cls}" title="${c.role} (${c.rank})">${c.emoji} ${c.label}: ${label}</span>`;
      }).join(' ');
    }
    
    document.getElementById('health-refresh-time').textContent = data.checkedAt || '刚刚';
  } catch (e) {
    console.error('loadSystemHealth error:', e);
  }
}

## Session Fork 流程

OpenClaw 2026.7.1 支持 session fork——在现有 session 基础上创建分支，
保留上下文的同时独立探索。

### 何时使用 Session Fork vs 新 Spawn

| 场景 | 使用方式 | 原因 |
|------|---------|------|
| 需要保留当前对话上下文做分支探索 | `sessions_fork` | 保留完整上下文，适合方案对比 |
| 全新独立任务，与当前对话无关 | `sessions_spawn` | 新 session，避免上下文污染 |
| 审微审核发现方案问题，需要修改 | `sessions_fork` | 保留审核记录，在分支上修改后合并 |
| 派发到六部执行具体任务 | `sessions_spawn` | 子 Agent 独立执行，不需要父 session 上下文 |
| 需要对比两种方案 | `sessions_fork`×2 | 从同一 session fork 两个分支，分别探索 |

### Session Fork 流程（审微封驳场景）

当审微（shenyi）审核方案后提出修改意见时：

```
1. 审微返回审核结论（含修改意见）
2. 主 Agent 在审微 session 上 fork 一个新分支
   sessions_fork(sessionId="审微的sessionId", task="根据修改意见修正方案")
3. 在 fork 上完成修改
4. 将修改后的方案提交给审微复审
5. 复审通过后，合并到主流程
```

### 决策规则

- **sessions_fork**: 当需要「保留某个子 Agent 的推理上下文，在其基础上做修改」
- **sessions_spawn**: 当需要「让子 Agent 从零开始独立执行新任务」
- **优先使用 sessions_spawn**，除非明确需要保留上下文做分支探索

)

# 派发新任务 → spawn
sessions_spawn(
  agentId="daima",
  task="实现 JJC-xxx 的代码开发功能"
)
